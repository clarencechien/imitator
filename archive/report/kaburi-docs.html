KABURI

一個資料夾，一張檯面

東西放上來、處理完、下檯。開一個固定資料夾裡的檔案，看、改、改名、存回原檔。

這是什麼

工作檯，不是倉庫

檯面上只該有你現在正在處理的東西。它不是倉庫，也不是檔案管理器——檔案怎麼進到資料夾不歸它管，所以怎麼刪掉也不歸它管。

是

  • 開一個固定資料夾裡的檔案
  • 看、改、改名、存回原檔
  • 暫時貼一段 token 的便條

不是

  • 檔案管理器
  • 倉庫、筆記庫、同步工具
  • 有搜尋、標籤、全文索引的東西

分工上：BentoDrop 運送、Kaburi 處理、SnapDeck 呈現。任何新功能先問它屬於哪一段，不屬於「處理」的一律不做。

檔案類型

六種副檔名，一張表

副檔名就是類型選擇器。+ 一律開 untitled.md，要別的類型就改名——沒有下拉選單。

.md .markdownmarkdown 算繪：標題、表格、清單、引用view
.html .htm沙箱預覽，腳本與外部資源都不會跑view
.json樹狀結構，物件與陣列可折疊view
.csv表格，表頭可勾、數值欄靠右view
.yaml .yml純文字加逐行上色view
.txt .log純文字，保留縮排，不解析任何語法edit

進 view 還是 edit，是推導的不是挑的

view 的產出跟原始碼明顯不同就進 view，一樣就進 edit。yaml 原本歸在 edit，加了上色之後它的 view 不再等同原始碼，依同一條規則改成 view。規則沒有例外，是輸入變了。

只有一個強調色

螢光綠標出「值」，key 與標點保持安靜。一個顏色是強調，一整套 token 配色才是語法高亮——後者屬於 SnapDeck。

▾ { 3 } service: "vector" ▾ tags: [ 2 ] 0: "ck" 1: "eap"

csv 的數值欄是逐欄推論的

一欄裡非空的格子全部都是數字，那一欄才算數值欄。文字欄裡夾一個 42 不會單獨跳色——逐格判斷在一欄文字中看起來像壞掉。開頭是 0 的當代碼不當數量，日期與布林值不上色。

UserIDNameJoinDatePhoneScore

102John2026-02-2009876543210.5

yaml 只上色，不解析

逐行用正則切出 key、值、註解、清單符號。它從不宣稱懂結構，所以對 anchor、多行純量、flow 風格永遠不會給出錯誤的判讀——一個「看起來對但結構是錯的」檢視比純文字更危險，因為你會相信它。上色也不更動任何一個字元。

# 掃描設定 root: key: value list: - one

白名單的職責不是「我們支援哪些格式」，是「存回去不會毀掉的檔案」。存檔是把字串寫回去的，二進位檔被當文字讀進來再存回去就永久毀了。這讓界線有客觀依據，不是品味問題。

不會偷改你的檔案

存回去的是你給的位元組

  • 只支援 UTF-8。解碼不過的檔案顯示提示、只給看，連 view／edit 開關都停用——不能讓人打了半天字才發現存不回去。
  • BOM 與 CRLF 會被還原。解碼器會剝掉 BOM、編輯區會把 CRLF 換成 LF；兩者都在讀取時記下、寫回時補回去。不改內容直接存，位元組完全相同。
  • 超過 1 MB 不開。該列仍留在檯面上，你看得到它存在。
  • 解析失敗不擋你。json 或 csv 解析不了就退回純文字加一條提示，不驗證、不報行號、不擋存檔。算繪是服務，不是驗證。
  • 節點太多就退回文字。免得手機被十萬個 DOM 節點拖垮。
檯面

最近五筆，其餘收起來

依修改時間排序只留最近五筆，其餘收在「這個資料夾裡的全部」後面。最近看的是「我剛才在忙什麼」，所以按日期分組；全部是「找特定檔案」，所以平鋪，檔名才是主角。

下檯不是刪除

左右滑（或聚焦後按 ← →）把檔案從檯面隱藏，完全不動磁碟。所以不需要確認、不需要復原——滑錯了再滑回來。

下檯記的是「檔名 + 當時的修改時間」。所以檔案被外部改動過會自己回到檯面、改名後舊紀錄自動失效、同名檔刪掉重建也會回來。不需要任何清理程序。

看與改

一顆膠囊，兩種狀態

一顆膠囊在看與改之間切換，顏色跟著換：冷光是看、暖橙是改。Save 只在改過之後才出現。點檔名就能改名，改名的覆蓋防護會擋掉同名檔——這是整個 app 唯一會讓你損失資料的地方。

便條

關掉就沒了

貼上、用完、滑掉。關掉就沒了——不寫磁碟、不進資料庫、不同步。複製並丟掉 一顆按鈕做完兩件事，這是貼 token 最常走的動線，併起來就沒有忘記清的機會。

不加 AI。要送到雲端 API 就跟「不落地」正面衝突，而且你自己會搞不清楚哪些東西出去過。

兩種佈局

全螢幕才攤開

不用視窗寬度決定，用有沒有全螢幕決定。一般視窗是單欄、底部分頁列，站在檯前快速處理；按下全螢幕才攤開成左側 rail 加檔案欄加工作區。

寬度是環境，全螢幕是意圖，只有後者該決定佈局。把視窗拉寬不代表你想攤開來看，只是視窗大。

不落地

沒有後端

  • 沒有後端、沒有分析、沒有第三方資源。整個站是四個檔案，讀完就能審完。
  • 檔案不離開你的裝置。Kaburi 直接讀寫你選的那個資料夾，沒有任何上傳。
  • HTML 預覽跑在沙箱裡。腳本、外部圖片、外部 CSS 一律不會執行或載入。
  • 分享進來的檔案在瀏覽器分頁裡一定要點一下才寫入，而且每份分享都綁一個一次性的權杖，別的網站塞進來的東西取不出來。
  • 存的只有偏好。主題、語言、下檯清單、csv 表頭勾選。內容一律不存。
