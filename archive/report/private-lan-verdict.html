資訊室通報單 · 條號 00 · 私架裁決

公司禁的不是網路線，
是你在長網段

「不能私架網路」是一句沒有拓樸的禁令。把桌機、GB10、筆電互連算不算違規，不取決於線是不是跳線、盒子叫不叫 Router，而取決於你有沒有自己發 IP、轉發封包、把未納管設備藏在公司網後面。

條號 01 · 定義

口頭禁令真正在管什麼

台灣公司資訊室講的「私架網路」，幾乎從來不是《電信法》裡的「架設公眾網路」。它是內部資安條款的口語：未經核准，在公司場地或公司網邊上，自己長出一截 IT 管不到的連通域。

條款要防的通常是這四件事，而不是「多插一條線」：

  • 未授權設備接入公司交換器或公司 Wi‑Fi。
  • rogue DHCP：第二個發 IP 的人，讓別人拿到錯閘道。
  • NAT／轉發：公司防火牆、代理、稽核只看得到你這台閘道，看不到後面的 GB10。
  • 雙棲主機：筆電同時接公司網與自建網，一開共用就變成 Rogue Router。

裁決句：有沒有「新網段＋閘道行為」。有，就是私架的核心型態；沒有，才進入「灰色、要問 IT」的區。

所以同一條網路線，可以是無害的點對點，也可以是違規的二層路由。線材不犯罪，角色才犯罪。

條號 02 · 設備

Hub、Switch、Router 差在職權，不差在外觀

賣場常把 Switch 叫成 Hub。真 Hub 是第一層廣播設備，半雙工、碰撞域共用，現在幾乎買不到。你手上那台八孔小盒子，多半是非網管 Switch。

角色 層 它做的事 會不會自己長網段
Hub集線器 L1 收到就廣播給所有埠 不會
Switch交換器 L2 依 MAC 把框送到對的埠 不會。只擴同一 LAN
Router路由器／分享器 L3 依 IP 連不同網路，常附 DHCP、NAT、Wi‑Fi 會。這是典型私架載具
Linux 桌機軟路由 L3 dhcpd／dnsmasq + ip_forward + iptables 會。盒子換成作業系統
一條跳線點對點 L1–L2 兩張網卡互連 不會。除非其中一台又開轉發

補充三件容易誤判的事：

  • 家用 Router 可關 DHCP、把 WAN 空著、當 Switch 用。設不乾淨就仍是路由器。
  • 現在網卡幾乎都有 Auto‑MDIX，兩台直連用普通網路線即可，不一定要交叉線（跳線）。
  • GB10 這類 AI 工作站互連，常有人想上 10GbE／直連以求模型與資料在本機跑。頻寬需求不改變資安定性：快線一樣可以是點對點，也可以是閘道。

條號 03 · 拓樸

三種接法，三種被看見的方式

孤立小 LAN，不碰公司網

[桌機]──┐
[GB10 ]──┼── Switch 或 一條線
[NB   ]──┘
        × 不接公司網孔
        × 不開公司 Wi‑Fi

技術上這是獨立廣播域。對公司骨幹沒有 rogue DHCP、沒有 NAT 繞過。資安條款若寫「禁止自備網路設備／禁止公司資產接入非公司網路」，仍可能違規；若只禁「私接路由器上網」，這段比較好辯。

公司網後面再掛閘道

公司網孔 ── WAN ── Router 或 Linux
                     ├── 192.168.x.10 桌機
                     ├── 192.168.x.20 GB10
                     └── 192.168.x.30 NB

這是教科書私架：新網段、DHCP、NAT。網管側常見線索包括 TTL 被減 1、同一 enthernet 埠出現多組 OS 指紋、DHCP discover 來自不該發 discover 的位址。

雙棲：比買分享器更糟

公司 Wi‑Fi ── NB ── 網路線 ── GB10（192.168.x）
               └── 若開 ICS／橋接／ip_forward
                   NB 本身就是路由器

筆電同時活在兩個網。未開轉發時，風險是「公司資產連到未納管設備」；一開轉發或「共用網際網路連線」，這台 NB 就是 Rogue Router，而且移動、難盤點、難關。

線是媒介。閘道才是私架。

條號 04 · 軟路由

Linux 開配 IP 再 iptables 轉到 192 的 GB10

這不是「Linux 比較不像架網路」。職權與家用分享器相同：

  • 配 IP：dhcpd、dnsmasq、NetworkManager shared、systemd-networkd 的 DHCPServer=。
  • 轉發：net.ipv4.ip_forward=1，nftables／iptables 的 FORWARD。
  • 藏設備：MASQUERADE／SNAT，讓公司只看得到這台桌機。
  • 入口：DNAT／port forward，把公司網上的埠轉進 192.168 的 GB10。
桌機一邊接公司網、一邊接 GB10，又開上述任兩項，裁決就是私架。作業系統不能當免責聲明。

若三台完全離線、Linux 只在孤立介面上發 192.168、不把公司介面納進 FORWARD，對骨幹傷害較小，但仍是自建閘道。要比這個更乾淨，就把 DHCP 與 forward 都關了，改兩邊靜態 IP、閘道留空。

條號 05 · 直連

跳線讓 Win11 筆電接 GB10，本身不像架網

點對點只有一個碰撞域、沒有中間盒、沒有第二個 DHCP 時，多數資訊室不會把「兩台機器一條線」寫進私架案例。它比較接近本機互傳。

要它維持「不像架網」，清單很短：

  • 當下關掉公司 Wi‑Fi 與公司有線，或至少不要讓兩個介面互相轉發。
  • 不要開 Windows 的 ICS、橋接、行動熱點。
  • 兩邊手動同一小網段，例如 192.168.50.1/24 與 .2/24，預設閘道空白。
  • 不要在其中一端開 dnsmasq 只「圖方便」。

連不上時先查的不是政策，是位址：APIPA 169.254.x.x 代表沒設靜態、也沒人發 DHCP；掩碼不同、一邊設了閘道指向公司，也會讓封包走錯口。

條號 06 · 裁決表

同一句「算不算」，要先填拓樸再填答案

高 · 幾乎就是

Router／軟路由 WAN 接公司網；開 DHCP + NAT；公司網孔下私接 AP；雙棲主機開轉發。

中 · 灰色

孤立 Switch 三台互連；公司場地放自備網路盒但不上行；直連但其中一台仍掛著公司 Wi‑Fi。

低 · 最不像

兩台直連、靜態 IP、無 DHCP、無 forward、當下只活在這一條線上。

行為 物理意義 資訊室通常怎麼看
發 DHCP 你在指定別人的閘道與網段 私架的強特徵
ip_forward / ICS / 橋接 你在當路由器 私架的強特徵
NAT / MASQUERADE 後面的裝置對公司隱形 私架的強特徵
自備 Wi‑Fi SSID 未核准無線基站 幾乎一律禁止
只接 Switch、靜態 IP、不上行 孤立同網段 看條款；先問再做
一條線兩台、閘道空白 點對點 多半不叫私架
最終解釋權在 IT，不在這份通報單，也不在你拿去問的另一個模型。模型只能幫你把情境寫清楚；核准只能來自承辦。

條號 07 · 問法

不要問「我可以架嗎」，問一句有拓樸的話

含糊的「不能私架」會把直連和二層路由捲成同一種罪。帶這句去問，對方才答得了：

三台設備（公司桌機、GB10、筆電）互傳資料，不接公司網孔、不開公司 Wi‑Fi、不開 DHCP、不開 NAT。只用一條網路線或一台非網管 Switch、兩邊靜態 IP。這樣算不算定你們說的私架網路？若不算，雙棲（筆電同時連公司網）有沒有另外禁止？

若對方只回「一律不行」，那是政策選擇，不是網路定義錯誤。此時不要用技術名詞辯贏，改走申請：臨時獨立實作網、專案 VLAN、或 IT 核發的交換器。

條號 09 · 附記

這份通報單不代替核准

網路定義可以寫死：DHCP、forward、NAT、雙棲，是閘道行為。政策不能寫死：有的公司連孤立 Switch 都禁，有的只禁上行 Router。GB10 放在座位底下、裡面是權重與資料時，即使直連也建議報備——出事時「我只是串 LAN」通常不會被當成理由。

先問承辦 比事後解釋拓樸便宜。
