架構筆記 · AGENT VS WORKFLOW · VOL.4 · 2026-10

它很會分，
但它不會想

Jev 式 typed decision 在 agent workflow 裡該放哪一段？答案不是「每個節點都用」，也不是「拿它來找 unknown unknown」。它是一台一次讀一欄、把卡片丟進編號口袋的分類機——這篇把它是什麼、不是什麼、哪些題能進機器、哪些不能說清楚，然後把它放回 workflow、agent loop 和人的 cascade 裡。

接回 VOL.2 的四象限與 gb10-typed-decisions 的十題實驗 · 外部評測取自 2026-09 至 10 月的 Jev 社群資料

PASS 0 · 讀法

一句話的主軸

Jev 是一個只會比對的節點，不是會思考的流程；它的價值不在它多懂，而在它把「哪些事已經可列舉」和「哪些事還不能」這條線畫清楚，讓 workflow、agent loop 和人各就各位。

這篇的每一段都在服務這句話。接回 VOL.2 四象限是用來決定「這個情境該用 workflow、agent loop 還是埋點」的；接回 gb10 十題實驗是用來決定「決定好之後，某幾個節點能不能用 Jev 實作」的。兩者是上下層，不是替代關係——這是整篇最常被弄反的地方。

PASS 1 · 它是什麼，不是什麼

一台很會讀題的比對機

IS · 它是

一台比對機。你給它輸入文字和一組選項，它只輸出一個字母，你讀那個字母的機率分佈。分佈只有三個來源：輸入文字、題目與選項怎麼寫、模型的預訓練先驗。它量的是「輸入和選項描述之間有多像」，用的尺是預訓練裡的知識。

零標註能跑，是因為語言和教科書知識底模早就有了。你的 200–500 筆標記從頭到尾沒碰到模型，只用來把「它說 95%」對應成「實際 82%」那張校準表。

規則住在 prompt 裡，不在權重裡。改規則是編輯文字，不是重新訓練。

IS NOT · 它不是

不是 oracle：它只知道你放進 prompt 的事加上先驗，不知道你不知道的事。不懂你們廠：教科書 SPC 它有，你們對某台機「抖」的定義它沒有。

不會新增選項：分支永遠是人畫的，Jev 只在既有分支裡選。機率不是證據量：輸入沒訊號時它照樣吐一個由先驗和選項位置決定的分佈，而且照樣 99%。

不會拒答，除非你給它一個「無法判斷」的選項。不能解釋。擋不住注入。

猜和讀從外面看長得一樣，差別只有校準之後才看得見。

86% 到 95% 那一跳是最好的例子。SPC 處置這題在你把廠內規則寫進選項文字之前，模型用的是世界通用的 SPC 常識，和你們的規則對不上，所以自信地錯；寫進去之後，它做的事從「判斷」退化成「對照」——拿輸入去比對 prompt 裡的規則。傳統 ML 要從標記裡把規則學出來，LLM 是規則給它、它負責套。這就是它「懂」的全部：讀出三種已知——輸入裡寫明的、選項文字裡定義的、它預訓練裡本來就有的。

PASS 2 · 題目是什麼，不是什麼

哪些卡片能進機器

一題要成為 Jev 題，五個條件要一起成立。缺任何一個，卡片就不該進這台機器。

  • 01

    選項現在就能全列出來，而且幾個月內穩定。列不出來的不是 Jev 題，是候選生成或探索。

  • 02

    答案是標籤，不是數字也不是解釋。數字走公式，解釋走生成，只有標籤走 Jev。

  • 03

    邊界可數，或至少改寫之後可數。不可數的要分辨是「規則沒寫清楚」（改寫，變回 Known Known）還是「真的要看證據才知道」（Known Unknown，Jev 只做排序）。

  • 04

    頻率高到每天百次以上。百次以下的決策讓人做比校準門檻便宜。

  • 05

    低信心時有人接，接完會回寫。接不住的不該上自動化。

四種不是 Jev 題的題

數字題交公式——產能異常公式 100% 對模型 93%，而 SPC 規則對數值序列本來就是可計算的，Western Electric rules 不需要語言模型。申論題交生成。邊界模糊的先改寫再進來，改寫前的 SPC 和警報緊急度其實是 Known Unknown 偽裝成 Known Known。最後一種最容易漏：從線索到輸入要跳兩步以上、中間那一步需要你們領域知識才接得上的題。規則說「黏度走勢像鋼板在乾就選 C」，模型得先知道黏度和乾掉的物理關係才能把兩邊接上；這段不在先驗裡時，prompt 裡的線索就只是 token，它會退回字面相似度——輸入裡哪個詞和哪個選項的詞長得像——然後照樣給你 99%。

A/B/C/D 為什麼降了一兩個量級，代價是什麼

輸出空間從無界縮到四個，「說得頭頭是道但錯」整類失敗消失。你不批改過程，所以路徑錯答案對也算對——小模型在 chain-of-thought 裡常把自己講歪，讀機率反而避開採樣雜訊。比對是這類模型最強的動作，申論是最弱的。代價是對錯只剩一個數字，答對的理由和答錯的理由你都看不到，所以校準不可省；而順序敏感是「懂」只到字面相似度為止的直接證據——真的懂的東西，不會因為選項從 B 搬到 C 就改答案。

PASS 3 · 它補了 LLM 哪裡

五件補得到的，六件補不到的

拿它跟「直接叫 LLM 生成」比，而不是跟 fine-tuned BERT 或 rule engine 比——後者才是它真正的同類，而且有標記資料的地方它們仍有競爭力。

LLM 的不足Jev 怎麼補但是
格式幻覺發明不存在的工具或選項永遠在 schema 內「不能給無效值」不等於「不會給錯值」
慢、貴不生成 token、多題平行。社群實測中位數快 7 倍省 30 倍不是官方的 193 倍與 444 倍；你量到的 2.4 倍落在 2–20 倍區間裡
信心不可量化「我很確定」是文字可校準、可設門檻、可進稽核紀錄的數字。RLHF 已知會傷校準，這是 Jev 存在的理由校準是對分佈的性質，不是對模型的；公平硬幣它答 0.92，骰子 1/6 它答 83%
冷啟動傳統 ML 標 100 筆還不到 90%零筆或 25 筆就能上，因為 ML 那 100 筆有一半花在學語言標記累積到兩千筆後，強題上小分類器大概追得上
規則改不動改規則要重訓規則在 prompt，邊界改了明天生效——棘輪便宜這才是它贏 ML 的地方，不是「比 ML 懂」

它沒補的六件：解釋、算術、日期排序、矛盾處理、字面閱讀、對抗輸入。TypeSafe 自己列的九個失敗模式裡就有這些，Check Point 的注入測試九種攻擊組合全破，「untrusted」標籤沒用，唯一有效的防禦是推理能力。這六件剛好都是「該在程式層做」的事，所以不是缺陷，是分工。

PASS 4 · CASCADE

一路往下掉，掉到哪層就是哪個象限

先拆一個誤區：象限不是入口能預測的。「資料有沒有」是查你的 tag 目錄，「知不知道該問什麼」是查你有沒有對應的 template，兩者都相對於系統現況定義，不在輸入訊息裡。出一題「這屬於哪個象限 A/B/C/D」，模型沒有你的 template 清單和埋點目錄，只能從語感猜，而且 99% 猜。Agent vs flow 同理是設計期的決定，runtime 只需要知道「命中哪一條現成的 flow」。

象限不是預測出來的，是輸入掉到哪一層、由那一層定義的。

層做什麼誰做答得出來就是答不出來
L0切訊息、算數值（SPC 規則、UPH、閾值）程式—不可能，必經
L1「這是哪一個已知 case」：N 個 template + 無法判斷，校準門檻JevKnown Known → workflow掉 L2
L2「這個症狀屬於哪個 playbook 家族」：M 類 + 無法判斷JevKnown Unknown → 候選生成 → Jev 排序（打折）→ 人確認掉 L3
L3「相關機台／站位／時段有沒有資料」程式查目錄Unknown Known → 有界探索 agent loop，Jev 當每步裁判與停止條件掉 L4
L4埋點需求單，不進任何 LLM人／資本支出Unknown Unknown終態

Playbook 是什麼：兩種 agent loop 的差別

L2 的 playbook 不是某個 agent 的設定檔，是「一個症狀家族的假設清單」：每個假設配一條可查的證據（查哪個 tag、看哪段時間、比哪個閾值）。它屬於 Known Unknown——假設空間已經列舉，只是不知道這次是哪一個——所以執行它的東西更像 workflow：照清單逐一取證、Jev 把證據對假設排序、人確認。它是一個已知的 loop：迭代的對象是一張人寫好的清單，步數有限，每步做什麼事先定好。

L3 的探索 agent loop 是另一種：沒有清單，只有資料。生成模型負責提出下一個查詢或假設，程式去跑，Jev 裁判「這條線索值不值得追／該停了嗎」，預算用完就停。它是一個有界的 loop：迭代的對象是 agent 自己生出來的查詢，上界是預算不是清單。兩種 loop 的分野就是四象限的那條橫軸——假設空間列得出來，用已知的 loop；列不出來但資料在，用有界的 loop。探索 loop 找到的東西經人確認後寫成 playbook，就從 L3 搬到 L2，這也是棘輪的一種。

棘輪：標籤是回溯出來的

L1、L2 的標籤不用人想，從歷史工單反推：每張已處理的工單當時走的是哪個 template、哪個 playbook，就是標籤，和校準門檻用的是同一批資料。棄答那一側的標籤則是回溯的：每一筆 needs_human 被人處理完之後才補標「其實是現有 template X（模型漏判）」、「是新 template（Known Unknown 轉成 Known Known）」、「是新 playbook」或「要先加埋點」。這四種回溯標籤就是 VOL.2 的棘輪——它們不只是訓練資料，而是直接改 L1、L2 的選項清單。所以象限標籤本來就會過期，做一份靜態標註集是錯的；正確的指標是前門棄答率隨時間下降，那條下降曲線就是「第 100 次與第 1 次的差」。

第二條 cascade：模型階梯，和上面那條正交

同一個節點，先 rule engine，再 E2B（派遣單位、升級、意圖、停工原因四題夠用），再 26B（派工程師、警報類型、根源站位、SPC、緊急度明顯強），26B 不確定才升人。你已經量化了 E2B 到 26B 那段有 6–13% 的差距所以成立；之後想加「26B 不確定就丟 Qwen 122B」這一層要先量——Janus 測過 Jev 接大模型的階梯，一個資料集有效，另一個一樣準但貴三倍。階梯不是預設有用的。

節點 Jev 化的正確理解

Workflow 裡原本的 if/else，條件判斷換成校準過的機率，這是「強化版 if/else」沒錯；但分支結構還是人畫的。Jev 從不新增選項，只有棘輪會。所以 Jev 不是 workflow 的替代，是 workflow 能吃模糊文字輸入的原因。

從社群搬來、要改一下才能用的四個模式

  • 拆題

    Composite scoring：把「警報緊急度三級」拆成影響範圍、是否持續惡化、有無備援幾個 yes/no 各問，權重寫在程式裡不寫在 prompt 裡。弱題拆成數個強題，合成留給程式——這就是「把跳數壓回一步」的具體形式。

  • 先取再判

    Retrieve-then-judge：塞無關內容準確率會掉（context rot）。對應你「多則訊息要在程式層先切」，也就是 L0 存在的理由。

  • 排序打折

    排序研究裡 53 列同時卡在 0.99 打平、batch size 一改閘門就翻。L2 的 Jev 排序只在機率有明顯落差時可信，高信心區段的相對順序不拿來做決定。

  • 當特徵

    標記累積到一定量後，Jev 的機率向量加 rule engine 的數值特徵，餵一個小分類器，可能比單靠任何一邊穩。Jev 負責冷啟動，不必負責終局。

PASS 5 · 綜效

四個東西各自不夠

Workflow 沒有 Jev 吃不了模糊輸入，只能處理結構化欄位；Jev 沒有 workflow 就會被要求回答它不該答的題——數字、申論、多跳。Agent loop 沒有 Jev 當裁判，每一步要花生成模型的錢去判斷「這條線索值不值得追」；Jev 沒有 agent loop 就只能在已列舉的空間裡打轉，永遠碰不到 Unknown Known。校準門檻是 Jev 和人之間的門，沒有它自動化會自信地派錯工；人沒有棘輪回寫，整套就是 VOL.2 說的「很貴的一次性函式」。

所以綜效不是「每個節點都用 Jev」，而是 Jev 把「可列舉」和「不可列舉」的邊界實作成一個可量測的棄答率，讓 workflow 接前者、agent 接後者、人接剩下的，而且邊界每週往外推一點。外面的社群用例集中在客服分流、內容審核、文件分類、agent 的工具選擇與 RAG 過濾；把它放回工廠 workflow、按模型大小分層，這部分外面幾乎沒有案例。

PASS 6 · 硬規矩

校準與部署，一份合併的清單

這是對話裡出現過的所有風險，合併成一份。每一條都有外部評測或你自己的實驗背書。

  • 校準集

    必須刻意放進「它應該不懂」的案例，不然門檻只量到它懂的那半邊，上線遇到混雜訊息就自信派工。合成資料數字偏樂觀，真實工單重校。

  • 盛行率

    校準對分佈敏感：jev-certify 在 CLINC150 上自動路由 84.75%，但 out-of-scope 比例一升，「誤路由不超過 5%」的保證就守不住。警報組成隨班別、機種、新產品變，門檻要跟著重新認證。

  • 棄答選項

    弱題明確給「無法判斷」，不能只靠門檻。KoBBQ 審計：有 unknown 選項時 95% 棄答，拿掉後同批題 0% 對、79% 選刻板答案。

  • 順序

    選項順序鎖定。弱題 20% 隨順序翻答案。

  • 數值

    全部在 L0 算完，不讓文字有機會覆蓋數據。「訊息裡寫『不急』就壓過數據」和 Check Point 的注入是同一種機制的良性版本。

  • 批次

    多題一次問、前綴快取開著（--swa-full）。社群：13 題一次問比分開問便宜 12 倍、快 10 倍。

  • 解釋

    Lazy：Jev 決定，生成模型只在被問「為什麼派給我」時補理由，理由不進決策路徑。

  • 微調

    只考慮 E2B／E4B 那四題，26B 別動。LLM2Jev：微調讓 0.6B 大幅進步、讓 4B 在覆蓋到的領域進步但在沒覆蓋的格式退步；只用意圖資料訓練會養出偏 yes、壓 fallback 的捷徑，要 KL anchor。韓國 K-Decision：政策題 83.1% 輸 Jev 93.3%，補一個合成資料 adapter 就追平——覆蓋解釋了大部分差距，缺的是橋樑不是參數。

PASS 7 · 待驗證

把「懂、讀 prompt、格式降難度」的比例量出來

用你 15 美元等級的預算做四組消融就夠。把選項描述拿掉只留標籤，掉分就是 prompt 規則的貢獻。把邊界規則故意改錯，看準確率跟著錯規則走（在讀 prompt）還是抵抗（先驗主導）。用生成模式先解釋再作答，統計「答對但理由錯」的比例，那是 A/B/C/D 幫你藏掉的部分。數值部分單獨交 rule engine，剩下的差距才是 LLM 真正負責的範圍。

再加上社群建議的三步：shadow-run 一到兩週、自己畫 reliability diagram（按信心分箱、算每箱實際準確率）、門檻等資料確認機率誠實之後再設。

兩個便宜的探針

判斷某題「它懂不懂」不用猜：生成模式要它解釋那個詞，看講的是不是你們的意思；還有順序敏感度——某題一打亂選項就翻答案，就是那題的橋樑斷了。

PASS 8 · WHOLE PICTURE

全部放在一起：一個大的 PDCA

前面每一段各講一個零件。把程式、Jev、workflow、兩種 agent loop、生成模型和人放回同一張圖，它是一個 PDCA：人在 PLAN 畫分支清單，runtime 在 DO 把每筆事件沿 cascade 往下掉，CHECK 把人確認的結果和模型答案對起來，ACT 是棘輪——而且 ACT 的四個動作「新 template、新 playbook、新 sensor、改邊界」是整個 loop 唯一會讓分支清單變長的地方。Jev 不會新增選項；這張圖裡只有左下角會。

八個落點，把情境窮舉完

Cascade 每一層都只有兩種結果，所以落點是互斥而且窮盡的：一筆事件不會同時落兩格，也不會沒地方去。

落點情境誰收Jev 在哪回寫什麼
S1數值可算：SPC 規則、UPH 閾值程式不在無
S2已知 case，高信心workflowL1 的決策節點抽樣稽核即可
S3已知 case，低信心人 → workflowL1 棄答校準資料 +1；若是漏判，改選項描述
S4有 playbook，不知道是哪個假設已知 loop → 人L2 分類 + 證據排序（打折）重複出現的假設 → 新 template
S5沒 playbook，有資料，探索找到有界 loop → 人每步裁判、停止條件新 playbook（L3 搬到 L2）
S6沒 playbook，有資料，預算用完沒找到人停止條件累積到一定量 → 可能是缺量測，開 sensor 單
S7沒資料人／資本支出不在新 sensor，L3 目錄 +1
S8輸入本身壞：多則混雜、注入、格式程式 → 人不在，L0 之前就擋切訊息規則 +1

讀這張表的方法是看空格。Jev 那一列在 PLAN 和 ACT 都是空的——它不畫分支也不加分支。生成模型那一列只在三個地方有字，而且沒有一個在決策路徑上。人那一列最滿，但 DO 裡的六個落點都是低信心出口，不是常態路徑；系統健康的指標就是那六格的流量隨時間往 S1、S2 搬。PDCA 轉一圈，分支清單長一點，前門棄答率低一點；這就是整套東西存在的理由。
