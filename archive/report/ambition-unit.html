野心的
單位變小了

五個午餐聊天的問題，兩個小時的牆上時間，其中 agent 工作了 36 分鐘，人坐在螢幕前大約半小時，換到一篇有模型也有驗算的報告。外送是上篇的事。這一篇記的是那兩個小時裡發生了什麼，誰做了什麼，錯在哪裡，花了多少。

01 · 起點

14:31 一份 Gemini 整理好的文件和五個問題進來。外送專法到底是什麼。Uber Eats 和 foodpanda 為什麼變貴。到底會多貴。別人走過這條路，台灣會怎樣。國外經驗能用嗎，都是同一家 Uber。

那份文件是 chat 時代的答案長什麼樣的標本。結構漂亮：執行摘要和四方矩陣，三地對照表，還有一個消費者棄用的臨界點模型。八成的數字查下去都是對的。問題出在剩下的兩成跟那八成寫在同一張表裡，用同樣的語氣。紐約官方報告的數據、DoorDash 遊說時的口徑、遊說團體對市場規模的推估，還有它自己發明的「溢價率超過 35% 到 40% 就棄用」模型，讀者分不出哪一格是地基、哪一格是裝潢。

它最大的問題不在錯，在它寫得讓人不會想追問。

上篇〈加薪留不住〉是這五個問題的答案。這一篇記的是從那份文件到那篇報告之間的兩個小時。

02 · 紀錄

下面是整個下午的流水帳。左欄是時間，中欄是人說了什麼，右欄是那句話造成的結果。agent 做的事沒有逐條列，因為量太大：二十二次搜尋和五次抓全文，讀了一篇論文的附錄，寫了一支腳本，跑了三組區間，出了三版報告，檢查器跑兩次。人這邊只有八句話。

還有一件事表格看不出來：人不在電腦前。從對話紀錄的時間戳算，14:31 到 16:34 共 123 分鐘，agent 從收到一句話到交出結果，加起來工作了 36 分鐘。其餘 87 分鐘是 agent 做完在等人。等的時間分兩種：十次 1 到 5 分鐘的短空檔，是人回來讀產出、想下一句；五次 10 到 25 分鐘的長空檔，是人在做別的事。把短空檔加上長空檔裡讀報告的幾分鐘，人真正坐在這件事前面的時間大約半小時。

04 · 收線的四次

釣竿是 agent 在甩。但四次改變結論的時刻，都是人判斷「線鬆了」。把四次攤開看，它們有共同的形狀。

一 「一小時只有一單，還有時薪嗎？」agent 的第一輪查核寫了「只保障接單後時間」，寫得很順，順到像是講完了。這一問逼出法條的真正結構，也逼出後面所有論點的起點：台灣的設計把空等的成本放在外送員身上。線鬆的訊號是：一句話講得太順。

二 「有沒有論文或模型？」在這之前，整件事是一篇查核加評論。這一問把它變成可以算的東西。附帶的那句「我不用訪問，用漲過之後的現況」更重要，它定了識別策略：消費者價格 8 月 14 日才動，所以前兩週的供給反應只看得到一個參數。線鬆的訊號是：結論有了，但沒有式子。

三 「先用真實資料，再開旋鈕。」沒有這一句，模型會變成三個口味參數的遊戲。有了這一句，平台公佈的兩週數據先把進入彈性釘住，剩下的旋鈕才有意義。線鬆的訊號是：參數太多，每個都能撥。

四 「店家也轉嫁了，外送價比內用價差三成。」這是 agent 自己沒看到的洞。v0.1 把商家那 2.5 個百分點記在「商家付」就停了，轉嫁率因此少算一倍。線鬆的訊號是：你自己的生活經驗跟報告裡的數字對不上。

agent 時代稀缺的技能，可能是在答案看起來完整的時候，決定還要不要再問一次。

鏡子篇說 AI 照出來的是你的信念。這個下午照出來的是另一樣東西：追問的習慣。四次收線沒有一次需要新資訊，需要的是對「完整」的不信任。

05 · 錯在哪裡

agent 在這兩個小時裡犯了四個錯。照記，因為它們是論點的一部分。

14:39 · 三分之一第一輪查核寫「台灣的地板只有西雅圖的三分之一」。下一輪自己查到：那是匯率。除以當地最低時薪之後，台灣 23% 對西雅圖 25%，幾乎一樣。這個錯是 agent 自己翻掉的，因為原句有數字，數字可以重算。
15:01 · 轉嫁率 0.25v0.1 只算了消費者服務費，沒算商家灌進外送菜單的那一塊。是人抓的。修正後店家那條線整個重寫，外送員那條線沒變。
14:53 · 平台的數據把進入彈性釘住的三組數字，全部是 Uber Eats 和 foodpanda 自己公佈的。平台有動機證明「外送員沒有更好」。這算出處問題，還不算錯誤，但它必須跟結論一樣顯眼。上篇把它寫在驗算那題旁邊，用一個警示框。
15:19 · 舊檔跑檢查器第一次跑的是改分號之前的版本，報了 11 個已經修掉的分號。重抓現行版本再跑才對。小事，但它說明流程裡每一步都要知道自己在看哪個版本。

Google 時代這些錯也會犯。差別在 chat 時代你看不到它們，每一格的語氣一樣。agent 時代每一個都有出處，所以錯得出來，也修得掉。agent 犯的錯沒有比較少，變的是錯誤可以修。

06 · 這個答案的代價

把對話紀錄裡每一次 API 呼叫的用量加起來。快取讀取算 0.1 倍，快取寫入算 2 倍，輸出算 5 倍，這樣加權比較接近實際的計價。紀錄從 14:54 換到工作環境之後才有逐筆的數字，前面二十三分鐘在另一個介面跑，只知道它留下了約 34 萬 token 的上下文，用同樣權重估約 90 萬。

三件事值得記。

查資料貴，但貴的地方不在查，在重讀。查到的 27 萬 token 留在對話裡，之後每一次呼叫都掃一遍，七十次掃下來佔了一半。這是 agent 工作方式的結構性成本：它記得的東西越多，每一步越貴。

真正輸出的字只有 7 萬 token，包含三版報告和所有回答。36 分鐘的工作，產出佔用量不到 2%，其餘都是讀。

換成人的時間，這個下午做的事，我的估計是一個經濟系研究生一到兩週：查三個城市的官方報告，讀一篇工作論文的模型，找台灣的數據，寫腳本，寫文章。但對照的另一邊要寫對。這個下午人花的時間是半小時，而且這半小時是從別的事情裡切出來的，像午餐時順口問一個問題，吃完飯回來看一眼答案。研究生的兩週是全職，這半小時是順手。兩週對上順手的半小時，這才是野心的單位可以變小的原因。

所以這個答案的代價有三層。第一層是 agent 的訂閱費，它把五百萬 token 和二十二次搜尋藏在鏡子後面，人看不到，也不用看。第二層在鏡子前面：人的半小時，和八句話裡改了結論的那四句。那四句沒有 token 可以買，它們來自追問的習慣，而習慣是之前花的時間。第三層是鏡子本身：agent 犯的四個錯都在對話紀錄裡，看得到才修得掉，這也是一種成本，叫作要有人看。

07 · 這是什麼野心

Felix Rieseberg 那篇〈How to be more ambitious〉講的野心，是去做本來會打消念頭的事。打消念頭的理由通常是成本：這要一個月，這要找人，這要先學一門課。

這個下午打消念頭的理由本來很充分。「Uber Eats 為什麼變貴」是午餐聊天的題目，拿它當研究題目做，要讀論文，要建模，要找數據，正常人不會為一個聊天題目花兩週。所以正常的結局是 Google 搜幾次，或者拿 Gemini 那份文件當答案。

兩週變成順手的半小時之後，那個理由不成立了。野心的單位從「專案」縮到「問題」：一個問題值得做到有模型、有驗算也有出處，因為做到那裡的成本已經低於「拿一份看起來完整的文件當答案」的風險。

野心的另一種定義：對更小的事，用同樣的標準。

harness-probe 那篇的結論是「跑從來不是問題，看才是」。這個下午是同一句話的另一個版本：跑的是 agent，二十二次搜尋，一篇論文，三版報告。看的是人，八句話。跑的成本降了兩個數量級，看的成本一點沒降。所以單位變小的同時，人的工作沒有變少，變的是它的位置：從做事移到判斷事情做到哪裡該停，該追問，還是該翻掉。

08 · 沒解的

這篇紀錄只跑過一次。一次成功不代表流程可重複，它可能只是題目剛好：外送專法剛好有論文，平台剛好公佈了數據，模型剛好只有一行式子。換一個題目，三個「剛好」可能少一個。

釘住進入彈性的數據只有平台有。agent 可以把這件事標出來，不能替代一個獨立的資料來源。這個限制在 Google 時代一樣存在，agent 沒有解掉它。

回家作業還是人的。上篇留了三題，哪一題值得追、什麼時候追，agent 排不出優先順序，因為那取決於你還關不關心這個問題。

09 · 回家作業

把這個下午的流程寫成一個方框，下一個午餐問題用同一套再跑一次。能跑第二次，這篇才算成立。

01 查核：先對別人的答案逐條找出處，標出歪掉的和漏掉的
02 追問：一句話講得太順的地方，問一次
03 找模型：有沒有人解過，式子長什麼樣
04 釘數：先用真實資料把能釘的參數釘住，再開旋鈕
05 跑區間：剩下的參數撥幾個值，看哪個真的會動
06 寫：每個數字標出處，自報的數據標利益方
07 標距離：拿到的事實離答案多遠，差距就是作業
08 記帳：花了多少 token，人說了幾句話，人坐在前面幾分鐘

候選題目一個：上篇第 8 題「沒問但冒出來的」那一條，外送員學會等疊單。它沒有現成的論文，平台數據只有一個接單率，模型要自己寫。三個「剛好」少兩個，剛好可以測這套流程。
