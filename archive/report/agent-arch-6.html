00 · 前情

VOL.3 的比價單少了一欄

接回 VOL.1 Q1 問控制流由誰決定：程式碼決定是 workflow，模型在執行期決定是 agent loop。接回 VOL.2 可枚舉與否、有沒有 oracle，交出 CELL A 到 D 四格。接回 VOL.3 Harness 不在 Q1 軸上，它決定錯了多貴。那一篇留下 RULE 05「買殼、寫流程、借迴圈」和三條鎖定軸，分別看模型、平台與狀態。

VOL.3 的比價單比的是程式碼框架，五家廠商的 SDK 加一欄自製。拖拉節點的畫布那一層沒有進表。當時的理由是它不屬於 harness，現在看是漏了。

補這一欄的起點是 X 上一則貼文。作者自稱在字節做過 Coze 的 workflow 引擎，他說 Coze 要下線了，並留下三個判斷：workflow 是被「模型自己會規劃」淘汰的；當年拼命做的拖曳節點是在替模型的笨拙買單，是 low-code 平台延續出來的過渡產物；怎麼搭工作流的技能已經被 agent 內化L4。

先校正標題。官方公告下線的是企業版：企業標準版與旗艦版 2026 年 11 月 30 日起停止新售，在火山引擎購買的舊版套餐 12 月 31 日下線，新版企業套餐最晚到 2027 年 12 月 31 日，理由寫的是「因產品整合安排」L1。個人版還在。那三個判斷值不值得信，要看 Coze 以外的案例。

Flowise 的公告是這張表裡講得最白的一份。團隊自己寫：「The typical rigid workflow low code approach quickly hits the limit」L1。OpenAI 的遷移指南沒給理由，但有一行限制值得抄下來：核心是強確定性的 workflow，可能無法忠實搬成 workspace agentL1。

有兩個案例我沒有算進來。Relay.app 在 7 月宣佈收攤，原因是創辦人和部分員工被 Google 聘走，產品沒有被買L4。豆包、千問與元寶在 7 月下架的是使用者自建 agent 的廣場，起因是 7 月 15 日施行的擬人化互動服務管理辦法L3。這兩件一件是人事、一件是監管，都跟畫布這個形式無關。

另一半原因是錢

IDC 的數字：2025 年中國公有雲的 agent 開發平台市場整體約 2.5 億人民幣，Coze 以 19.3% 排第一L3。兩個數字相乘大約 4,800 萬，這是推算，Coze 沒有揭露過營收。同一年私有部署的市場是 17.5 億L4。市占第一的產品落在一個小池子裡，這件事跟模型能力無關。

因果要分開標。「被模型自己會規劃淘汰」在 Flowise 是官方自己寫的。在 Coze 只有一則自稱前員工的貼文，官方說的是產品整合。OpenAI 沒給理由。

去處倒是一致。六個案例裡，沒有一個把使用者送去另一塊畫布。去處只有兩種。一種是文字，包括 prompt、skill 與用自然語言描述的 agent。另一種是程式碼。

02 · 主軸

畫布裝過兩樣東西

2024 年在畫布上拉一個節點，可能是在做兩件不同的事。

第一件是寫推理步驟。先搜尋，再抽欄位，依金額分支，然後把結果丟給下一個 prompt。這是人用滑鼠替模型回答 Q1。VOL.1 的 Q1 只有兩個答案，程式碼或模型。畫布上的推理節點是第三個答案，由人畫。它成立的前提是模型自己規劃不好。

第二件是寫確定性流程。觸發與重試，憑證更新，寫回 CRM，等人簽核。這是 CELL A 的 workflow，本來就該由程式碼決定，畫布只是它的一種寫法。

接回 VOL.3 那一篇引過 Anthropic 的說法，harness 的每個元件都編碼了一個「模型自己做不到」的假設，這些假設值得被壓力測試。推理節點正是這種元件。假設失效，元件就該拆。確定性節點不一樣，模型再強，API 還是會逾時。

Lindy 把這條路完整走了一遍。最早的版本讓使用者在一個大文字框裡描述要自動化的事，2.0 改成方塊加箭頭、自稱 Zapier of AI，2026 年 2 月的 Lindy Assistant 又回到對話介面L4。同一家公司，從文字到畫布再回到文字。

推理搬去文字，確定性留在流程。只裝推理的畫布，被搬空了。

所以那則貼文的前兩個判斷大致成立，第三個要改寫。被 agent 內化的是「替模型排步驟」這門手藝。排確定性流程的手藝還在，而且 03 會看到，它現在多了一個工作：把 agent 框住。

03 · 收斂

兩頭往中間收

如果 02 是對的，應該看得到兩個方向的移動：從「全用畫的」出發的產品把推理交出去，從「全用 prompt」出發的產品把確定性加回來。2026 年兩邊都有。

產品出發點2026 年做了什麼級
Dify全用畫的8 月 27 日 New Agent 進 beta：模型驅動的 ReAct 迴圈，加上隔離的 Linux sandbox，以及 Skills 與 MCP 工具。Agent 變成可以被多條 workflow 重用的資源L4
騰訊雲 ADP 4.0全用畫的6 月 5 日發佈，新增支援 agentic loop 的 Claw 模式，Agent 與 Workflow 可以雙向互調。副總裁的說法是模糊開放的事交給 agent，確定的流程交給 workflow，省 tokenL3
Gumloop全用畫的改以 agent 當主要介面，workflow 變成 agent 可以呼叫的東西L3
Coze 3.0全用畫的5 月底發佈，支援多人多 agent 協作，可接 Claude Code、Codex CLI。三個月後團隊併入豆包L3

有人一年前就講過

2025 年 10 月，OpenAI 在 DevDay 推出 Agent Builder 的隔天，LangChain 的 Harrison Chase 寫了一篇解釋為什麼 LangChain 不做視覺 workflow builder。他的論點是這類產品被兩頭擠：複雜度低的交給 no-code agent，複雜度高的要寫成程式碼，中間那段越來越窄L2。LangChain 後來做的是用自然語言描述來建 agent 的工具，2026 年 1 月 GA，3 月改名 LangSmith FleetL1。

八個月後 OpenAI 宣佈淘汰 Agent Builder。遷移指南只給兩條路，Agents SDK 或 Workspace Agents。一條是程式碼，一條是自然語言。

04 · 修正

n8n 是修正，不是反例

最容易寫錯的地方在這裡。Coze 收攤、n8n 估值翻倍，順手的解釋是「n8n 做的是確定性管線，不碰 AI」。我查到一半時差點這樣寫，資料不支持。

n8n 的投資方 Felicis 引述，2025 年 n8n 上超過 80% 的 workflow 涉及 AI agentL3。另一份第三方分析看了 4,650 個 workflow，只有 25% 含 AI 節點L4。兩個數字的母體和定義都不同，我對不起來，列在 08。不管採哪一個，n8n 的畫布上都有不少 AI。分界線不在「畫布上有沒有 AI」。

差別要從 n8n 執行長 Jan Oberhauser 今年 9 月的訪談裡找L2。他講的幾件事，逐條對回 02：

  • 畫布是拿來看的。他強調的用途是檢查與稽核：看得到建了什麼，也看得到每一次怎麼跑、每一步進出什麼資料。
  • 圖可以不是人畫的。示範裡他用一段 prompt 請 AI assistant 建 workflow，AI 想了大約八分鐘，交出一張帶審核步驟的圖。
  • 常見的路徑是先文字後畫布。他說很多人先用 Claude Code 做原型，再搬到 n8n 跑正式的。
  • AI 是其中一種節點。他的說法是 AI 加確定性邏輯加 human in the loop，一個 if 比模型便宜、快，而且百分之百可靠。
  • 產物帶得走。可自架，workflow 可匯出，模型可換，還能設備援模型。

他同時報了幾個數字：年經常性營收過 1 億美元，活躍使用者 150 萬，企業客戶 1,200 家，公司有獲利。這些是執行長自述。外部可查的是 2026 年 5 月 SAP 的策略投資，估值 52 億美元，並把 n8n 放進 SAP 的 Joule StudioL3。

n8n 沒有反駁 02，它示範了留下來的畫布長什麼樣。圖的作者換成 AI，人退到審查的位置。畫布從作者的工具，變成審查的介面。

接回〈每一層〉 那一篇的結論 8 寫「下一代平台的 UI 是審批面板，不是設定面板」，當時標的證據強度是中、偏推論。Coze 的畫布是設定面板，設定模型怎麼想。n8n、Copilot Studio 與 Agentforce 現在畫的是護欄、簽核和例外處理。這一條可以往上調。

要注意說話的人。賣畫布的人說畫布重要，這是他的立場。

反證要並列

一份分析自動化範本的研究指出，n8n 範本裡只有 1.2% 含明確的人工核准步驟L4。這是公開範本，不是正式環境的資料，原始頁面我也只讀到摘要。但它提醒一件事：畫布「可以」當審批面板，和大家「真的」在上面放審批，中間還有距離。

分界線可以收成三個問題。推理由誰寫，是人畫的節點還是模型在執行期自己規劃。圖由誰畫，是人拖出來的還是 AI 生成後由人審。產物能不能帶走，也就是能不能匯出、自架與換模型。Coze 型的畫布，三題的答案是人畫，人拖，帶不走。

第四條軸：模型壽命

VOL.3 的模型軸問的是「能接哪些模型」。這次多出來的問題是「供應商多快把模型從你腳下抽走」。

Coze 的模型下線通知頁是一手資料L1。頁面開頭就寫，模型下線後，用到它的線上 agent、workflow 與應用都無法正常運行。2026 年的下線分五批，從 3 月 31 日到 10 月 22 日，每批間隔一到三個月。最具體的一筆在 5 月。5 月 11 日那批，多數型號的建議遷移目標是 doubao-seed-2-0-lite-260215。10 月 22 日那批，這個型號自己在下線名單上。照建議搬過去的人，五個月後要再搬一次。

各家寫在政策裡的通知期差很多：

供應商政策寫的最短通知期級
Anthropic公開發佈的模型，退役前至少 60 天L1
OpenAIGA 模型至少 6 個月，特化版本至少 3 個月L3

這條軸對畫布的傷害比對程式碼框架大，原因在 02。畫布上每個推理節點都有一段對著某個型號調出來的 prompt，節點越多，換模型要重測的東西越多。

推理收成一段文字交給模型自己規劃之後，換模型要重測的是驗收。驗收是 VOL.1 的 oracle，它本來就不該跟著模型變。

06 · 工廠版

地端場景，第四條軸反過來

沿用 VOL.3 的前提。環境在地端，外網受限，地端與雲端模型雙跑，可觀測性也全在地端，主要任務是事件檢討。整節是設計建議。

  1. 託管畫布出局。平台軸就過不了，這跟它收不收攤無關。
  2. 可自架的畫布過得了平台軸。Dify、n8n 與 MaxKB 都在這一類L2L3。接地端模型的 tool calling 品質要自己量，這一點跟 VOL.3 第 06 節的結論相同，瓶頸在推論伺服器。
  3. 模型壽命在地端是你自己的事。型號是你架的，沒有人會寄下線通知。代價是什麼時候升級由你決定，重測的成本還在，只是時程在自己手上。
  4. 按 CELL 決定畫布放哪。CELL A 的資料搬運、告警分派與開工單，用 n8n 型的畫布或既有的 job runner 都可以，畫布的好處是產線工程師看得懂、稽核看得到。CELL B 的事件檢討照 VOL.3 做，推理段寫成 prompt 加輸出契約，放在 bounded loop 裡，不要在畫布上拉成一串推理節點。CELL C 買殼。
  5. 人審接既有的簽核。04 那個 1.2% 是提醒。工廠已經有工單系統，human in the loop 接那裡，不要在畫布上另做一套沒人看的核准節點。

一個可以馬上做的檢查：把現有畫布上每個節點標成「推理」或「確定性」。推理節點連續出現三個以上，就是 2024 年的畫法。收成一個 agent 節點加一份文字指示，確定性節點原地不動。

07 · 規則與反模式

RULE 05 修訂、RULE 06 增補、RULE 09，AP-25–28

  • RULE 05（修訂）· 買殼、擁有流程、借迴圈VOL.3 寫的是「workflow 永遠自己寫」，改成「自己擁有」。可以用畫的，可以讓 AI 生成，但產物要能匯出成檔案，能在自己的機器上跑，也能換模型。n8n 活著跟原本的寫法衝突，跟修訂後的不衝突。
  • RULE 06（增補）· 鎖定看四軸原本的模型、平台與狀態，再加模型壽命。挑平台時多問三件事：政策寫的通知期多長，去年實際下架幾次，下架那天你的東西會不會停。
  • RULE 09 · 推理寫成文字，確定性寫成流程兩種東西不要用同一種節點畫。推理步驟放 prompt、skill 或 md，交給模型在執行期規劃。會產生副作用的步驟，以及需要重試或簽核的步驟，放流程。
  • AP-25 · 畫腦在畫布上用一串節點替模型規劃。模型每升級一次，這串節點就多一分多餘，而且拆它的成本由你付。
  • AP-26 · 借來的畫布流程只存在別人的託管畫布裡，手上沒有匯出檔。停售公告出來那天，才讀到匯出安排另行公告。
  • AP-27 · 把收購當保證以為被大公司買走的開源專案會一直有人維護。Flowise 被收購後不到一年就凍結，凍結後公告的高風險漏洞沒有修補版L4。開源授權保證你能 fork，不保證有人修。
  • AP-28 · 追著型號調節點每個節點的 prompt 綁一個型號。型號半年內就可能下線，節點有幾個，就要重調幾次。

回到最初那個問題，low-code 假裝是 harness 的，是不是都下課了。這一題的兩個詞都要換掉。收攤的那一型沒有在假裝 harness，它做的是替模型手畫計畫，那件事既不是 workflow 引擎也不是殼。留下來的畫布也還是 low-code。它們只是不再裝推理，改裝確定性流程和給人審的地方，有幾家開始長出真的殼，例如 sandbox、權限與稽核。

08 · 未決

還沒解的，和什麼會推翻這一篇

  • n8n 的 AI 佔比。80% 和 25% 差太多。一個是投資方引述的平台數字，一個是第三方工具 Synta 的使用者樣本，我沒有辦法對齊。
  • 人審的實際使用率。只有範本資料，沒有正式環境的資料。
  • Zapier 的 18% 只代表前四分之一。一般使用者的比例可能更低，也可能因為 AI 用得淺而完全不同。
  • Dify 那篇定位文是社群成員寫的，由官方轉載，不能當成公司聲明。
  • 仍在賣託管畫布加 prompt 節點的產品，例如百煉的應用編排、千帆 AppBuilder，我只查到產品動態，沒有營收或留存。

推翻條件先寫下來。如果 2027 年有一個純託管、推理由人在畫布上畫，而且不能匯出的產品還在成長，02 的主軸就要改。如果下一次模型世代更新後，留下來的畫布也開始把確定性流程交給模型在執行期寫程式完成，RULE 09 的後半句也要重看。
