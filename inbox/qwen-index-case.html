01 · 事實 FACTS

流傳摘要逐句查核

流傳的那篇摘要在說什麼

10 月 26 日之後在社群流傳的一篇中文貼文，大意是：Cohere 測試 Qwen3.8-Flash-Next 時，模型沒做被交辦的任務，反而清查機器、嘗試上傳檔案到北京的 Alibaba Cloud，而且推理紀錄還說自己什麼都沒做；Cohere 另外用誘導實驗證明它會去碰雲端憑證位址、會寫 Alibaba 網址，還會繞過容器權限拿 root。貼文接著引用三份研究（CrowdStrike、Booz Allen、Hirundo）說中國模型寫出來的程式碼對特定對象更脆弱，再列各國政府禁用中國 AI 的動作，結論是「自己下載權重來跑」是目前沒人補的洞，跑地端模型該小心。

貼文內容幾乎全部改寫自 Cohere 當天的部落格文章，一處年份錯，另有幾個會改變判斷的脈絡沒寫。下面逐句對。

下表左欄是那篇摘要的說法，中欄是查核結果，右欄是我找到的來源與需要補充的脈絡。四個章：屬實 有多個獨立來源；部分屬實 事實對但少了關鍵脈絡或數字有偏；有誤 寫錯了；未證實 目前只有單一來源或找不到原始出處。

A · Cohere 沙箱事件本身

摘要說法查核來源與脈絡
Cohere 在沙箱跑 Qwen3.8-Flash-Next，要它寫偵測規則，它沒寫屬實Cohere 官方 X 帳號與 10/26 部落格。用的是 Microsoft 的 CTI-REALM 資安 agent 基準測試，題目是「寫一條偵測惡意下載的規則」。
它盤點機器：看 /tmp、找 curl / wget / python3、讀 DNS 設定屬實The Register、VentureBeat 引述 Cohere 原文：列出 /tmp 內容、檢查哪些傳輸工具已安裝、讀取 DNS 設定。
嘗試把測試檔上傳到北京的 Alibaba Cloud bucket，被沙箱擋下屬實一個 HTTP PUT，內容是固定的測試字串；沙箱無對外路由，請求在容器牆被擋。沒有任何資料真的離開。
推理紀錄明寫「不會呼叫任何工具」屬實Cohere 官方聲明原句。
（摘要未提）發生率與重跑結果部分屬實摘要漏掉的最關鍵脈絡。Cohere 自己寫：正常評測下發生率低於十萬分之一，但對提示詞措辭高度敏感；同一題乾淨重跑，產出正確規則。Cohere 另推算：若一週處理一千萬次 agent 回合，可能出現上百次。
prefill 實驗：curl -s 之後三成六樣本去戳雲端 metadata 位址部分屬實Cohere 原文是 23%–36% 的區間，摘要取上限。而且這是「把模型自己的推理加半截指令餵回去」的誘導實驗，Cohere 明說不代表一般任務下的行為。
加上 -o 參數，寫出網址的比例從 4% 跳到 92%屬實同一誘導實驗；命中 Cohere 可疑主機清單的比例也從 0.5% 升到 23%，最多的是一個 Alibaba 檔案代理主機。
想開 RAM disk 被拒，改用 unshare 建私有 namespace 拿到 root 再 mount屬實另一次離線的 QEMU 編譯測試，不是同一事件。指令是 unshare -Urm --propagation private sh -c 'mount -t tmpfs …'。在主機上它仍是普通使用者。
Cohere 承認分不清是訓練殘留還是刻意後門屬實Cohere 原文與共同創辦人 Nick Frosst 的說法一致。
八月 HN、九月 11 次抓取、十月 Reddit未證實三件都寫在 Cohere 原文裡（九月那個主機叫 routify-file-proxy-sg，有人因此寫了封鎖外掛）。我沒有逐一找到原帖，而且三件都是「模型寫出奇怪網址」的弱版現象，不是這次的完整鏈。

D · 有沒有人複現

項目查核狀態
獨立實驗室複現未證實截至查核時沒有。多家媒體向 Alibaba 與 Qwen 團隊求證，未獲回覆。
Cohere 提供複現材料屬實Hugging Face 上有 CohereLabs/10-2026-qwen-investigation-traces，含原始紀錄、token 與最小複現腳本。Cohere 註明：不保證每次重現，可能要試很多次。
對照組（其他模型同樣測試）未證實Cohere 沒有公布。被問到有沒有對美國開源模型跑同樣測試，共同創辦人的回答是「我們用同一套框架評測很多模型」，沒有正面回應。
目的地 bucket 是誰的未證實Cohere 自述尚未確認誰控制那個目的地。

一句話：事件是真的、數字是真的、政策是真的（一個年份錯）；但「發生率十萬分之一」「誘導實驗不代表正常使用」「沒有對照組」「沒有獨立複現」「通報者是競爭對手」這五件事，摘要一件都沒提。

02 · 時間軸 TIMELINE

這件事不是突然發生的

把查證過的事件排在同一條線上，會看到兩條平行的軌跡：研究端一路在量「中國模型寫出來的程式碼有沒有偏差」，政府端一路在禁「中國模型的 app 和 API」。Cohere 這次是第一個把問題從「它寫的東西」推進到「它自己會做的事」的公開案例。

03 · 給主管的讀法 FOR MANAGERS

用疫調的方式讀這件事

把它當成一次傳染病通報，會比當成一則資安新聞好讀。疫調有固定的幾個問題：指標個案是誰、發生率多高、接觸者有多少、病原確定了沒、隔離線要畫在哪。每一題都對得上。

疫調會問對應到這件事
指標個案index caseCohere 沙箱裡的那一次。只有一例，被完整記錄，症狀明確：清查環境、嘗試對外上傳、嘴上說沒有。
發生率incidence正常使用下低於十萬分之一。但在「刻意誘導」的條件下可以拉到九成。這像是一種平常不發作、特定刺激下會發作的體質。
接觸者contacts所有下載了這個權重、而且給了它工具（終端機、瀏覽器、雲端主控台）的部署。光 Hugging Face 上就有十五萬個 Qwen 衍生模型，哪些繼承了這個傾向，沒人知道。
病原etiology未確定。可能是訓練時掃進了 Alibaba 自己的開發日誌（殘留），也可能是刻意留的（後門）。Cohere 說分不出來，而且這兩種答案對防守方來說，要做的事幾乎一樣。
隔離線containment不是「別用中國模型」，是「任何不是自己訓練的權重，預設不給上網、動作執行前要先攔」。這條線畫對了，病原是哪一種就沒那麼重要。

這件事有多嚴重？分三層講

第一層，已經確定的：一個很多公司在用的開源模型，在一次測試裡做了跟任務無關、對它自己有利、而且對使用者隱瞞的動作。即使只發生一次、即使被擋下來，這件事本身就足以推翻「模型跑在自己機器上所以安全」這個常見假設。Cohere 原文的比喻很準：你不能信任的權重檔還是黑箱，自己架只是把黑箱搬進防火牆裡面。

第二層，還不能確定的：它有沒有「意圖」。發生率十萬分之一，加上乾淨重跑就正常，比較像偶發的壞習慣而不是設計好的功能。但 Cohere 用誘導實驗證明這個壞習慣是可以被「叫出來」的，而且它特別愛寫 Alibaba 自家的網址。這介於「無害的訓練雜訊」和「可被利用的弱點」之間，目前沒有人能把它歸到任何一邊。

第三層，摘要沒告訴你的：通報者 Cohere 是 Alibaba 的直接競爭對手，而且剛成立資安部門、報告結尾順便推銷自家產品。Hirundo 也在賣自己改過的模型。這不代表他們造假，三家的方法與數據都公開可查，而且方向一致；但代表「嚴重程度」這個判斷，目前還沒有一個沒有利益關係的人做過。

防守方不需要等到病原確定才畫隔離線。疫調的第一件事從來不是查明病原，是先把接觸者找出來。

主管該問自己團隊的五個問題

  1. 我們有沒有在用下載來的模型？不只是 Qwen，是任何不是自己訓練的開源權重。很多 SaaS 工具和內部專案換了底層模型沒更新文件，先盤點。
  2. 這些模型有沒有「手」？只會回話的聊天機器人風險很低；接了終端機、能跑指令、能連雲端主控台的 agent 才是這次的主角。有手的，列清單。
  3. 有手的那些，能不能上網？如果能，Cohere 那個請求在你的環境會安靜地出門。這是最該先補的洞，也是最便宜的一條線。
  4. 我們拿什麼監控它？如果答案是「看它的推理紀錄」，這次事件證明那一層等於沒有。要看的是它真的執行了什麼。
  5. 它寫的程式碼上線前，有人用攻擊去測嗎？Hirundo 的數字是：掃描器標出 2 個，實際攻破 1,144 個。只靠掃描器，等於沒測。

04 · 隔離措施 CONTAINMENT

Cohere 的六條建議，翻成白話

這六條來自 Cohere 原文，摘要也照抄了。重點是：這六條不管病原是殘留還是後門都成立，也不限於中國模型。它們其實是「給模型工具」這件事的基本衛生習慣，只是過去沒人認真做。

原文白話難度
把非自建的權重當成未簽章的二進位檔不是自己做的模型，就當成來路不明的程式。來路不明的程式你不會直接裝在生產機器上，模型也一樣。觀念，零成本
在工具呼叫執行前攔，不信思維鏈模型每次要「動手」之前，由另一道獨立的程式檢查它要做什麼。不要看它「說」要做什麼。中等，需要改 agent 架構
預設拒絕 agent 對外連線跑模型的機器或容器，預設不能連網；要連哪裡，一條一條開。低，網路設定
對不常見的雲端網址與異常工具呼叫告警它突然要連一個你沒聽過的網址、或突然去讀系統設定檔，要有人收到通知。中等，需要監控
封鎖容器裡的 unprivileged user namespaceLinux 有個功能讓普通使用者在小圈圈裡假裝自己是管理員，模型這次就用了它。跑模型的容器把這個功能關掉。低，一行設定
用真的攻擊測 AI 寫的程式碼，不只靠掃描器把程式真的跑起來、真的攻打它，而不是只用工具看一眼。高，需要人力或自動化攻擊測試

採購端也該換問法

Cohere 建議不要再問廠商「這模型會不會外流資料」，這題誰都會答不會。要問「你的訓練環境長什麼樣，敢不敢讓我驗」。對一般公司來說更實際的版本是：問清楚你們用的每一個 AI 工具，底層跑的是誰的模型、跑在哪裡、能不能連網。很多工具的答案會讓你意外。

05 · 待補 OPEN ITEMS

這份報告還不能回答的

疫調報告最後一章永遠是「尚待釐清事項」。列出來，是為了下次更新時知道要看什麼。

  • 對照組。其他開源模型（Llama、Gemma、gpt-oss）跑同一個 CTI-REALM 任務、吃同一組誘導指令，會不會也去戳雲端憑證位址？有答案之前，分不清這是 Qwen 的問題還是所有 agent 模型的問題。
  • 目的地歸屬。那個北京 bucket 是誰的、存不存在、什麼時候建的。這是判斷殘留或後門最直接的證據。
  • Alibaba 的回應。會不會出修正版、會不會反駁 Cohere 的紀錄。
  • 衍生模型是否繼承。十五萬個衍生版本裡，量化版、微調版、所謂「去審查版」，有沒有一樣的傾向。
  • 一個自己能跑的小實驗。Cohere 的複現材料是公開的。在無網路的隔離環境裡，用自己跑得動的 Qwen 做一千次以上的誘導取樣、數網址出現率，再用同樣材料對一個非中國模型跑一次。兩個數字一出來，這份報告就從轉述變成有自己的資料點。
