01 硬體與作業系統定位：Framework 13 vs MacBook

影片核心結論並非 Framework 硬體缺陷，而是 Linux 桌面生態在行動工作站上的水土不服。

❌ Linux 筆電核心痛點

  • 待機休眠耗電 (S2Idle)：現代 x86 待機易背景喚醒，放入背包常發熱掉電；Framework 擴充卡特定插槽有暗電流耗損。
  • 非整數縮放 (Fractional Scaling)：3:2 螢幕在 125%/150% 縮放時，XWayland 與 Electron 軟體易模糊。
  • 除錯成本高昂：「修好一個驅動又冒出新 Bug」，日常辦公維護摩擦力過大。

最佳工程師工作流解法

  • 端點（Client）：MacBook (Apple Silicon) 提供 14-18h 極致續航、開蓋即用與免維護電源調校。
  • 伺服端（Server）：將 Linux 回歸 24h 插電的 Home Lab / 伺服器 / Headless 容器運行。
  • 無頭容器化：在 Mac 上僅運行無 GUI 的 Linux 核心，徹底消除桌面端顯示與驅動 Bug。

02 macOS 無頭容器架構與 Apple vz 調校

底層原理：容器依賴 Linux Kernel（cgroups / namespaces），macOS 是 XNU 核心，先天無法「原生」跑 Linux 容器。因此 Mac 本機必備一個微型 Linux VM，但完全無需安裝肥大的桌面 GUI。

Colima 效能榨乾公式（Apple Virtualization.framework）：

colima start --cpu 4 --memory 8 --vm-type vz --mount-type virtiofs --vz-rosetta

vz Apple 原生虛擬化

替代舊型 QEMU，直接調用 Apple Silicon 硬體指令集，CPU 損耗近乎為零，待機極度省電。

virtiofs 共享檔案系統

解決 macOS 與 Linux 共享目錄 I/O 緩慢問題，大幅提升 Node/Python/DB 讀寫效能。

05 Dockge 企業級安全與 PAM 治理架構

門禁反向代理 (Authentik / SSO)

  • 能力：對接企業 AD/LDAP，提供 SSO 與 MFA 入口阻擋。
  • 限制：Dockge 缺乏內部權限矩陣，通過 Authentik 放行後，全員皆擁有 Root 最高修改/刪除權限。
  • 定位：適合「全員皆為 Admin/DevOps」的單純集中認證情境。

特權存取治理 (OSS PAM / 堡壘機)

  • 工具代表：JumpServer (GPLv3) 或 Teleport。
  • 解決邏輯：以「流程控制 + 全程錄影稽核」取代細部 RBAC。
  • 核心機制：臨時權限提單審批（JIT）、Web 畫面全程錄影、SSH 危險指令阻斷。
